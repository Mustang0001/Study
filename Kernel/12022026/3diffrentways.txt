# 🔹 What You CANNOT Do (While Still Using Linux)

You cannot:

No driver modification can eliminate those.

# 🔹 What “Complete Custom Pipeline” Actually Means

If you modify the driver, your new pipeline becomes:

NIC DMA
→ custom RX descriptor ring
→ memory region you control
→ mmap into user space
→ your software polls descriptors

No:

* skb
* socket()
* TCP/IP stack
* netfilter
* copy_to_user
* kernel buffering

At that point, Linux is only:

* Initializing hardware
* Managing page tables
* Keeping system alive

That is 90% bypass.

And yes — you can do that.

# 🔥 But Here’s the Critical Constraint

Raspberry Pi 4 GENET NIC is:

* Not PCIe
* Integrated with SoC
* Limited documentation compared to Intel NICs
* Not designed for user-space polling mode drivers

So your customization depth is limited by:

* Hardware descriptor structure
* DMA design
* Register access constraints

You cannot redesign the NIC behavior itself.

You can only control how Linux interacts with it.

# 🔹 What a Real Custom Driver Pipeline Would Involve

You would:

1. Download Raspberry Pi kernel source.
2. Study `bcmgenet.c`
3. Understand:

   * RX descriptor layout
   * DMA address mapping
   * Interrupt flow
4. Remove skb allocation path.
5. Allocate contiguous DMA region.
6. Expose that region through `mmap()` in a character device.
7. Implement userspace polling loop.

Your app would then:

* Directly check descriptor status bits
* Read packet from DMA buffer
* Clear descriptor ownership bit

That is true driver-level control.
